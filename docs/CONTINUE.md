# 从新对话继续本项目

本页是独立对话的交接入口。先读 [README](../README.md) 了解工具和边界，再读 [案例记录](CASE_STUDY.md) 核对事实、时间线与证据，最后按具体任务打开源码。仓库文件是当前可复核的项目资料；新的对话不会自动拥有原对话的全部过程、终端环境或未发布日志。

## 项目范围与当前状态

- 目标：帮助定位 VR 具身机器人 Ego Data 采集中的 **设备 → PC Service → 本机 SDK → 应用** 数据断点。
- 已完成：标准库 Python 命令行工具 `teleop-link`（代理环境检查、TCP 可达性、JSONL 位姿统计、日志标记统计、本机 SDK 子进程代理隔离）；XRoboToolkit PC Service **v1.0.0** 的源码补丁和构建脚本；案例分析与离线测试。
- 不在此仓库：原始个人机器人项目、头显端应用源码、上游 PC Service 完整源码、已编译服务库、真实设备日志，以及机器人/夹爪控制程序。因此只凭本仓库无法重放当时的整套真机实验。
- 原创通用代码按 MIT 发布；适配器中的上游衍生补丁保留 Apache-2.0 来源和许可说明。

## 已知证据与不能推断的事

1. 用户在另一台电脑遇到同类“读不到手柄”症状，整体迁移个人工程后，在当前电脑上先成功读取、后来又遇到类似症状。更换电脑本身不能证明两个时刻的根因相同，也不是只改变一个变量的实验。没有已证实的“更换 PICO 头显”记录。
2. 一个断点位于 PC Service v1.0.0：持续 Tracking 数据可能仍被专用心跳的 20 秒在线计时判离线；同一设备标识重连后，上线通知也可能缺失。证据是上游源码、服务日志及模拟 TCP 设备的连续 Tracking／超时／重连验证。补丁只适用于已核对的 v1.0.0 源码。
3. 另一个断点位于本机 SDK 的代理环境：失败终端的绕过列表包含 `localhost`，不包含 SDK 使用的字面地址 `127.0.0.1`。在同一组代理变量下，仅隔离 SDK 子进程代理后，读数从 **179/179 零时间戳**变为 **148/179 非零时间戳**。这组对照支持代理影响本机连接；代理变量由哪个应用设置，尚无证据。
4. 后续只读记录 **563/594** 帧时间戳非零，其中右手柄位姿有效 **233** 帧。它证明当次数据到达应用，不证明任何以后运行都不会再掉线。用户确认 VPN 在成功与失败时都开启，不能写成“关闭 VPN 修好了问题”。

详细时间线和验证边界以 [CASE_STUDY.md](CASE_STUDY.md) 为准。若将来有新日志，应按发生时间、设备 TCP、服务在线状态、本机 SDK 连接、时间戳及位姿分别记录；不要仅凭“全零”表象直接选补丁。
